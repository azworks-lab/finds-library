# FINDS — проверенная загрузка изображений (22.10.2026)

## Состояние

Рабочий эксперимент подтверждён **только в ветке `finds-v2-image-test`**. Ветку `main` не изменять без отдельного согласия владельца. Сохранить дизайн и функциональность V2.

### 1. Автоматическое скачивание GitHub Actions по URL — ПРОВЕРЕНО

Файлы:
- `.github/workflows/test-remote-image.yml` — тестовый workflow.
- `data/image-import-test.json` — задание с URL изображения.
- `images/test-remote-import-schell.jpg` — тестовый результат.
- `data/image-import-test-result.json` — контрольные байты и SHA-256.

Процедура проверки:
1. Workflow реагирует на push в `data/image-import-test.json`.
2. GitHub Actions получает JPEG по HTTPS, проверяет сигнатуру, конец файла и размер до 5 МБ, сохраняет файл и JSON с SHA-256.
3. Workflow коммитит результат в **тестовую ветку**.

Подтверждённый успешный запуск: GitHub Actions **Test remote image import**, run ID `39833252997`, commit `fccd0230b6d24e0ca5066a34d2fc8905dda7811a`. Файл SCHELL 5655 байт. Git blob SHA исходного и повторно скачанного изображения совпадает: `2a116f7784a614447021b31941c13aace02ab8c1`.

**Ограничения текущего теста:** workflow разрешает URL только с `raw.githubusercontent.com/azworks-lab/finds-library/`, записывает изображение под фиксированным тестовым именем, **пока не обновляет** `data/products.json` автоматически. Для реальных карточек нужно доработать конфигурацию: product ID + допустимый публичный URL, безопасная проверка адреса/типа файла/размера, имя файла, обновление photo в JSON, коммит, проверка отображения. Не утверждать, что это уже реализовано.

### 2. ZIP-импорт — проверенный резервный способ

Workflow: `.github/workflows/import-product-images.yml`.
- Реагирует на push файла `finds_images_inbox.zip` и поддерживает ручной запуск.
- Ожидает 1–100 изображений с именами вида `<product-id>.jpg`, `.jpeg`, `.png`, `.webp`.
- Проверяет ID товара, формат и размер до 10 МБ на файл.
- Копирует изображения в `images/`, обновляет поле `photo` в `data/products.json`, удаляет ZIP, коммитит результат.
- Предусмотрен запрет работы в `main`.
- Этот маршрут уже использовался при наполнении каталога. Автоматическую передачу ZIP **непосредственно из ChatGPT в GitHub** отдельно не подтверждали; не обещать её без проверки.

### 3. Не повторять неудачный путь

Прямая передача JPEG через GitHub `create_blob` с вручную перенесённым Base64 привела к несовпадению байтов одного изображения; следующая попытка была заблокирована средой. Синтетические Base64-тесты успешны, но **для реальных фото предпочтительнее GitHub Actions по URL**. Не возвращаться к ручному копированию Base64.

### 5. Принцип работы

Пользователь сообщает модель товара или ссылку. Ассистент находит публичный URL фотографии производителя/магазина, GitHub Actions загружает и валидирует фото, обновляет карточку, затем проверяется результат. Фото, присланное пользователем в чат, — резервный сценарий через ZIP. Минимизировать ручные действия пользователя. Вся разработка/проверка — только в тестовой ветке до явного одобрения переноса в `main`.
