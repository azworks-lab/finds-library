## Зачем это нужно
FINDS — личная библиотека удачных товарных находок, не интернет-магазин и не отдельная работа по вечерам. Цель — пользователь сообщает о покупке, а система по возможности сама находит данные, изображение и обновляет карточку.

## Сохранённые элементы V2
- Мобильный тёмный интерфейс, название FINDS, подпись «Личная библиотека товаров», иконки `icon.svg` и `finds-mark.svg`.
- 27 товарных карточек на момент фиксации; статусы «Куплено», «Выбрано», «В комплекте», «Кандидат»; категории, подкатегории, поиск, фильтры, раскрытие карточки, технические характеристики, заметки, связанные товары и ссылки.
- Сортировка «Новые» по умолчанию и «А–Я». Для карточек без `addedAt` резервный порядок — обратный порядок записи в каталоге. При добавлении нового товара ОБЯЗАТЕЛЬНО заполнять `addedAt` (ISO YYYY-MM-DD).
- Последние добавленные: VIDEX GX53 8 Вт 3000 K (4 шт.), чёрная однофазная шина VIDEX 2 м + 4 светильника, SCHELL COMFORT 04 907 06 99 (2 шт.), hansgrohe Logis 100.
- VIDEX лампа: SKU магазина `VLE-GX53-08533`; 8 Вт, 3000 K, 730 лм, 140°, цена 2,99 €/шт., 4 шт. Изображение магазина иллюстративное и показывает маркировку иной модификации (12 Вт / 4100 K / 1170 лм). Данные конкретного купленного товара имеют приоритет над маркировкой на общем фото.
- Правило фотографий: изображение серии допустимо, если внешний вид совпадает; отдельное изображение нужно при существенном различии формы, цвета, конструкции, комплектации. При заметно отличающейся маркировке указывать «Фото иллюстративное».
- Для Githack-предпросмотра исправлялись проблемы кэша: в `index.html` отключается регистрация Service Worker для raw.githack.com, удаляются старые FINDS-кэши; каталог запрашивается с уникальным параметром. На GitHub Pages офлайн-режим оставлен.
- Фотографии VIDEX и Logis отображались на телефоне после исправления адресов и обновления страницы. У VIDEX используются immutable raw.githubusercontent.com URLs, у Logis — аналогично.
- Автоматизация фотографий: `docs/IMAGE-IMPORT-PLAYBOOK.md`, workflow `import-videx-images.yml` (загрузка из точных URL страниц товаров через og:image), `repair-logis-image.yml` (проверенный успешный запуск), `import-product-images.yml` (резервный ZIP), `test-remote-image.yml` (эксперимент).
- Источник истины для карточек: `data/products.json`.

3. Убедиться, что свежие изменения каталога появляются в тестовой версии после обычного обновления без очистки кэша.
4. Проверить PWA и offline-поведение отдельно на GitHub Pages / в безопасной тестовой среде: raw.githack.com не равен production origin.
5. Разобраться с ошибками `Build offline library` — этот workflow ранее завершался неудачей; не считать его исправленным.
6. Отделить экспериментальные workflows, тестовые данные и повреждённый старый `images/hansgrohe-logis-100.jpg` от релизного состава. Не удалять без проверки ссылок.
7. Провести проверку всех файлов/путей изображений и валидности JSON; отдельно проверить, что дальнейший автоматический импорт не перезапишет исправленные URL.
8. Подготовить сравнение тестовой ветки с `main`, сделать релизный тег/резервную точку отката, запросить явное согласие владельца и только затем переносить.

## Правила работы
- До отдельного согласия не изменять `main`.
- Изменения дизайна и функциональности тестировать в `finds-v2-image-test`; сохранить историю `finds-v2-design`.
- Не заявлять, что изображение работает, пока оно не проверено в интерфейсе; успешный workflow доказывает только успешное выполнение задачи.
- По возможности выполнять операции через GitHub Actions без ручного скачивания и загрузки изображений владельцем.
- Для следующего чата: начать с этого файла и `docs/IMAGE-IMPORT-PLAYBOOK.md`, проверить состояние GitHub, продолжать с тестовой ветки.
