# FINDS — PROJECT PROTOCOL

Версия: 1.1 (2026-10-29). Этот файл — подробный технический протокол проекта; фактическое состояние кода и GitHub Actions необходимо проверять перед работой.

## Назначение
FINDS («Библиотека находок») — персональный каталог купленных, выбранных товаров и отдельных кандидатов, которые пользователь явно решил сохранить. Не каталог всех рассмотренных вариантов. Пользователь сообщает о покупке или выбранной модели, ChatGPT берёт на себя проверку модели, характеристик, карточки, изображения, запись в GitHub и проверку результата. Рутинные ручные операции пользователя — дефект процесса, который следует устранять автоматизацией.

## Инфраструктура
- Репозиторий: azworks-lab/finds-library
- Production: main
- GitHub Pages: https://azworks-lab.github.io/finds-library/
- Каталог: data/products.json
- Интерфейс: index.html
- Изображения: images/
- PWA: manifest.webmanifest, service worker
- Автоматизация фото: scripts/localize_product_images.py, .github/workflows/localize-product-photos.yml

## Процедура работы
1. В первую очередь открыть этот протокол и прочитать актуальные файлы по указанным здесь путям (в частности, `data/products.json`), а также релевантные workflows; не угадывать пути и не полагаться на память. При 404 сначала проверить существование репозитория, затем фактическую структуру, не делать вывод о недоступности GitHub по одному отсутствующему файлу.
2. Проверить, нет ли уже согласованного решения и существующего механизма.
3. Внести минимальные изменения, сохранив согласованные архитектуру и дизайн.
4. Проверить коммит и нужную ветку, выполнение workflow, файлы, Pages и конечную функцию, насколько доступно.
5. Сообщить отдельно: что реализовано, что проверено и что пока не подтверждено.
6. Если выявлена новая техническая причина изменения протокола, зафиксировать её здесь.

## Товары и карточки
- Пользователь может дать название, артикул, ссылку или сообщение о покупке.
- Проверять точную модификацию, характеристики, производителя, артикул и отсутствие дубликата.
- Разделы: Инструменты; Электрика и освещение; Мебель и интерьер; Сантехника и ванная; Бытовая техника; Отопление и вентиляция.
- Фактические поля и статусы определяются по data/products.json. README может быть устаревшим.
- Не придумывать цену, дату покупки, продавца или свойства.
- Отклонённые и промежуточные варианты не добавлять без явного решения.
- Пользователь может явно попросить сохранить отдельную модель как «Кандидат». Это согласованное назначение карточки, но **не означает, что статус уже реализован в интерфейсе**. Перед записью проверить допустимые статусы в текущем JSON и в `index.html`, фильтры и оформление. На 2026-10-29 в каталоге встречаются только «Куплено», «Выбрано», «В комплекте»; «Кандидат» требует отдельной реализации и проверки. Не подменять его статусом «Выбрано» и не объявлять карточку опубликованной до проверки.
- Перед добавлением проверять дубликаты по модели и артикулу; изменения данных не должны ломать сортировку, поиск, ссылки и отображение карточек.

## Изображения
Предпочтительный поток: модель/ссылка → поиск фотографии точной модификации → проверка → автоматическая загрузка GitHub Actions → images/ → локальный путь в карточке.
- Пользователь не должен скачивать, пересылать или переименовывать картинки.
- Источники: производитель или надёжный продавец, с учётом прав использования.
- Внешний URL — временная мера, а не подтверждение локализации.
- При сбое проверять лог workflow, скачивание, сохранение файла, обновление JSON и отображение на Pages.
- Не создавать дублирующие workflow без необходимости.

## Интерфейс и релизы
FINDS V2: сохранять визуальный стиль, логотипы, мобильную и десктопную адаптивность, навигацию по разделам и подразделам, поиск, фильтры, сортировку новых товаров сверху, раскрывающиеся карточки и браузерную навигацию назад/вперёд.
main — production. Рискованные изменения тестировать в отдельной ветке, затем переносить. Наличие изменения в тестовой ветке не означает наличие в main.

## PWA
Публичный URL должен работать, приложение устанавливаться и обновлять каталог при сети; офлайн-доступ к уже закешированным данным должен сохраняться. Избегать необходимости ручной очистки кеша и переустановки. На Android проверенная установка через Chrome; Samsung Internet ранее выдавал предупреждение Play Protect. Не рекомендовать обходить защиту.

## Контроль статусов
Различать:
- Запланировано — решение принято.
- Реализовано — файл/код изменён.
- Проверено — функция или механизм испытаны.
- Опубликовано и проверено — результат доступен в production.
Нельзя считать commit SHA или создание workflow доказательством конечного результата.

## Краткие описания в шапках карточек
- Для каждой карточки шапка должна содержать короткую, законченную по смыслу формулировку без обрыва на многоточии; ориентир — не более двух строк на мобильном экране.
- Использовать отдельное поле `preview` для краткой формулировки, когда полное `specs` не помещается. Если `preview` отсутствует, интерфейс показывает `specs`.
- `preview` описывает тип товара и 1–2 главные отличительные особенности; не дублирует длинные технические характеристики, не содержит непроверенных утверждений.
- Полные характеристики сохранять в `specs` и `details`, не сокращать их ради шапки. При добавлении и изменении товаров проверять отображение на узком мобильном экране и отсутствие визуального многоточия.

## Общение
Кратко, по-русски, технически точно, без повторения решённых вопросов. Если нужно участие пользователя — максимум 2–3 шага за раз. Сначала самостоятельно выполнить доступные действия. Не обещать результат, который не подтверждён.

**Основное правило: FINDS должен экономить время пользователя. Если для обычного пополнения каталога нужны ручные загрузки, чистка кеша или обходы, исправлять автоматизацию, а не превращать обход в норму.**
